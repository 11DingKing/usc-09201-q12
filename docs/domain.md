# 林产品批次履历领域约定

项目面向集体林权改革与林下产业协作场景，业务记录需要区分来源、发生时间与当前有效版本。涉及个人、机构或敏感地点的信息只应向职责范围内的角色开放，所有对外结果都应能够追溯到采用的数据版本。

## 核心不变量

1. **追加式事件溯源**：系统状态（批次余量、位置、等级、锁定、检验结论）完全由事件流推导。既有事件不可改写、不可删除；任何"修正"都是一条新事件。
2. **链路不可改写**：迟到检验、批次重编号、部分报废、跨仓转移、重复扫码都不得改写既有的合批/拆包链路：
   - 迟到检验以真实采样时间（`occurredAt`）追加，结论按**当时有效**的标准版本判定；
   - 重编号只追加新编码（别名），旧编码与链路关系保持不变；
   - 部分报废、跨仓转移只影响余量与位置，不影响来源组成；
   - 重复扫码凭幂等键去重，同一业务动作只生效一次。
3. **比例组成**：合批与拆包按数量比例记录物料流向。成品的来源含量 = 沿链路按比例分摊，支持菱形链路（先拆后合）。
4. **标准版本化**：质量标准按产品 + 生效时间版本化；检验判定与追溯结果必须标明所依据的标准版本。
5. **最小可见**：供应商（林农）只能查看与自身相关的批次、追溯与处置；其他供应商、地块与下游客户身份对其脱敏。批次、事件、登记信息的写操作仅质量负责人可执行。

## 关键概念

- **批次（batch）**：物料的最小追踪单元。由采收创建，经合批（多对一）、拆包（一对多）派生；余量随交付、报废、合批、拆包扣减。
- **物料流向边（lineage）**：`{from, to, quantity}`，合批/拆包时追加，是追溯的唯一依据。
- **失效模拟**：给定批次失效时，含其物料且仍有库存的批次构成锁定范围；已交付部分按客户汇总为下游通知清单；库存余量按仓库汇总。模拟本身只读，`applyLock` 才产生真实锁定事件（幂等）。
- **处置（disposition）**：锁定、报废、检验不合格的总称，从事件流推导，按角色过滤可见性。
